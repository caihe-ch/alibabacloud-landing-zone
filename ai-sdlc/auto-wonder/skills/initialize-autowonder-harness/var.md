# 客户项目变量

数字人 SOUL.md / AGENT.md、SDLC 描述、步骤指令及 checklist 只使用以下三个变量。模板母版保留占位符，初始化时在独立副本中替换。

## 变量清单

| 变量 | 客户提供的内容 |
|---|---|
| `{{CUSTOMER.DATABASE_CONFIG}}` | 整段 Markdown 数据库说明：数据库类型、授权目标、访问方式与凭据引用，以及适用的备份恢复、迁移和校验约定。 |
| `{{CUSTOMER.DEPLOYMENT_CONFIG}}` | 整段 Markdown 部署说明：部署环境、分支、目录、完整命令及工作目录、服务替换授权、端口、健康检查、日志和持久化数据保护要求。 |
| `{{CUSTOMER.FRONTEND_TEST_URL}}` | 独立的前端测试地址配置块：完整 URL，以及必要的网络访问和测试身份获取说明。 |

数据库、部署信息按整块描述填写，不拆成更多变量。前端测试地址不扩展为测试框架、资产目录或命令等变量。仓库信息及技术栈以平台仓库配置为准，测试工具和资产沿用目标仓库现有配置；这些具体信息不写入模板，也不另设变量。

## 可复制填写示例

将以下三块内容填写为对应变量的完整字符串值；尖括号内容须换成实际信息。密码、令牌、私钥不写入配置或 Git，仅提供受控凭据引用。

```markdown
### DATABASE_CONFIG
- 数据库：<类型与版本；唯一授权目标的端点、库名、schema 或文件绝对路径>
- 访问：<连接方式、必要参数与凭据引用>
- 变更：<适用的备份恢复、迁移执行与校验约定>

### DEPLOYMENT_CONFIG
- 环境：<环境、分支、部署绝对目录、端口>
- 执行：<工作目录、完整部署/停止命令、执行条件与服务替换授权>
- 验证与保护：<健康检查地址及成功标准、日志、持久化数据保护要求>

### FRONTEND_TEST_URL
- 地址：<前端测试完整 URL>
- 访问：<必要的网络访问说明与测试身份凭据引用>
```

## 初始化与核验

1. 读取所选模板与客户提供的三块信息，仅补问本次需要但缺失的内容。客户明确无数据库或无前端时，在实例副本中移除对应业务操作；不把“不适用”拼进命令执行。
2. 先解析配置 JSON，在已解析的字符串字段中按完整 token 替换；同一变量的全部出现位置使用同一值，再序列化。不要替换序列化后的整段 JSON，不执行模板命令来验证替换。
3. 替换值不得包含未解析标记。写入前递归扫描所有字符串，确认只使用上述三个变量且替换后无 `{{CUSTOMER.` 残留，缺失值和未知变量必须先处理。
4. MCP 写入携带工具支持的全部已读取字段，包括未改值和 `null`。结构化 ID 从目标空间解析，不能放字符串占位符或沿用源项目绑定；初始化范围仍以 [SKILL.md](SKILL.md) 为准。
5. 写入后回读数字人正文、流程描述、步骤指令/checklist/gate/路由/顺序及关联绑定，逐字段核对完整性和替换值，确认无截断、无残留。只报告核验结果，不回显秘密，不把客户实际值写回模板母版。
